# greenfield-report

Оперативная отчётность проекта «Гринфилд-1»: журнал проекта и ежедневный дашборд.

Обезличенный демонстрационный репозиторий. Данные вымышленные, метод рабочий.

## Что делает

Проверяет план из `data/plan.csv`, вычисляет статусы и готовность по правилам
`docs/spec.md`, сравнивает с последним снимком из `data/history/` и собирает один
самодостаточный HTML-файл в `build/`. После успешной сборки пишет снимок за отчётную дату.

Если данные плана негодны (пустой или нецелый вес, повтор кода, нет обязательной колонки
и т.п.), сборка останавливается с перечнем ошибок по строкам, код выхода 1. Файл
дашборда и снимок в этом случае не пишутся.

## Запуск

```
python src/build_dashboard.py --as-of 2026-09-17
python -m pytest tests -q
```

Необязательные параметры: `--plan` (другой файл плана), `--history` (другая папка
снимков), `--out` (другой файл дашборда).

## Снимки

`data/history/<дата>.json` хранит состояние на каждую отчётную дату. Блок «Что изменилось»
сравнивает с последним снимком раньше отчётной даты. Папку не удалять и не править вручную:
без снимков блок показывает «Нет базы для сравнения».

## Проверка на телефоне

Раскладку на экране 375 пикселей проверяет `tools/check_mobile.py` (проверки 12, 13, 17, 20
в `docs/benchmark.md`). Запускается вручную при каждом изменении `render()` или стилей,
до публикации. Playwright в репозиторий не входит, ставится один раз:

```
pip install playwright
python -m playwright install chromium
```

Запуск после сборки, из корня репозитория:

```
python tools/check_mobile.py --shot build_375.png
```

Каждая проверка печатается строкой OK или FAIL, код выхода 1 при любом FAIL.
Снимок `build_375.png` просматривается глазами. В `build/` его не класть.

## Структура

```
data/     исходные данные: plan.csv, journal.csv, risks.csv; history/ снимки
docs/     spec.md (правила расчёта), benchmark.md (критерии приёмки), backlog.md (долг)
src/      build_dashboard.py (сборка и вид), rules.py (правила и проверка данных), history.py (снимки)
tests/    test_rules.py, test_render.py, test_history.py, test_validation.py: автопроверки
tools/    check_mobile.py: ручная проверка на экране 375 пикселей
build/    результат сборки
```

## Регламент

Дашборд пересобирается ежедневно до 17:00 и внеочередно при изменении плана.

`tools/check_mobile.py` (проверки 12, 13, 17, 20). Запускается при каждом изменении
`render()` или стилей, до публикации.
